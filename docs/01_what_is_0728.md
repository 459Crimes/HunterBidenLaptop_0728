# 1. What Is 0728?

> **Encyclopedia.** Main article: [README](../README.md). Index: [all pages](INDEX.md). Related: [Glossary](GLOSSARY.md) · [R-Studio tree](R_STUDIO.md) · [Scope](SCOPE.md).

**0728** is the shorthand used in this project for **Extra Found Files**: a **recovery-software export tree** associated with **Conan James Hayes**, stamped **28 July 2021**, reaching this author in **August 2021** when **Garrett Ziegler** shared **Hayes’s MEGA link** (author: **first person known to download** from that link).

This repository is about that tree. It is **not** a laptop filesystem. **JPMI, APFS, and GAI are other objects.** Shared SHA-256 values are joins, not identity of media.

## A useful mental model

For a general reader, 0728 is a **bag of recovered files poured into type folders**, not a Mac home directory.

A working Mac copy (JPMI, APFS) has `Users/roberthunter/Library/Mail`, Photos libraries, CNIDs or APFS object IDs, and a volume header. Extra Found Files has folders named `Graphics, Picture/JPEG Image` and files named `0442396.jpg`. That is what commercial **signature recovery** (R-Studio Known File Types and similar) writes when it cannot or does not restore original paths.

## Important technical qualification

The July 2021 recovery utility session is **not** established from logs. Hayes’s **account** is unallocated carving; the **measurements** reject that account as origin of the unmatched remainder ([carving claim](HAYES_CARVING_CLAIM.md)). The accurate formulation is:

> **0728 is an R-Studio-structured recovery/export tree, MEGA-delivered after 28 July 2021, attributed to Conan James Hayes, represented here by path/hash/mtime inventories — not by a forensic image of the volume scanned, and not by unallocated space of the original 256 GB NVMe or of Hayes’s APFS / GAI.**

## What the repository actually possesses

The Extra Found Files bytes themselves are not published in this GitHub repository.

The project works from received inventories that describe the tree, including:

- relative paths and synthetic filenames;
- sizes and mtimes;
- SHA-256 identities;
- category/extension rollups;
- exact-hash joins to APFS, GAI, and JPMI.

Accordingly, this repository speaks authoritatively about **reported structure, paths, hashes, timestamps, and cross-source identity**. The GitHub project does not independently re-read every Extra Found Files byte from `source/recovered/` in a public clone; it is a metadata-and-hash witness.

## Why 0728 matters

Public discussion often collapses “the laptop” into whatever folder someone unzipped from MEGA. 0728 is useful because it is **large, named, dated, and only partly explained** by the three primary laptop-lineage catalogs.

Instead of asking only:

> Is this document present?

0728 allows questions such as:

- Which recovery bucket was it poured into?
- Does its SHA-256 exist on APFS, GAI, JPMI, some combination, or none?
- Is the basename original or synthetic?
- Does the mtime look like July 2021 export, 2026 working-copy handling, or a preserved content date?
- Does Hayes’s carving story match allocated-file overlap?

That is the distinction between **content evidence** and **provenance evidence**.
